# Fitli — פיטלי 🌱

אפליקציית React Native אמיתית, Expo SDK 57 ו־TypeScript, בעברית וב־RTL. הגרסה המקומית כוללת בניית מסגרת שבועית, אומדני תזונה אישיים, יומני ארוחות ואימונים ומעקב מדידות. אין צורך בחשבון ענן או במפתח API.

## פתיחה במחשב

כתובת שרת הפיתוח שהופעל במשימה: **http://localhost:8081/**. השרת חייב להמשיך לפעול כדי לפתוח את תצוגת הפיתוח.

אם השרת נסגר, פתחו PowerShell:

```powershell
cd fitli-app
npm ci
npx expo start --web
```

פתחו את הכתובת המודפסת בטרמינל. אם 8081 תפוס, Expo עשוי להציע פורט אחר. Node.js ו־npm זמינים במחשב שבו נבדק הפרויקט: Node 24.20.0, npm 11.19.0. להתקנה במחשב אחר: [Node.js LTS](https://nodejs.org/en/download).

**לשמירת הנתונים הקיימים השתמשו באותה כתובת ובאותו פרופיל דפדפן.** `localhost` ו־`127.0.0.1`, פורטים שונים, חלון פרטי או טלפון שומרים נתונים נפרדים. אין לנקות את נתוני האתר. `npm ci` מתקין תלויות ואינו מאפס את הפרופיל או ההיסטוריה.

## הרצה בטלפון

1. התקינו בטלפון [Expo Go](https://expo.dev/go), בגרסה התומכת ב־SDK 57.
2. חברו את המחשב והטלפון לאותה רשת Wi-Fi.
3. אם שרת Web כבר פועל, אפשר להשתמש ב־QR שבטרמינל שלו. לחלופין, הפעילו:

```powershell
cd fitli-app
npm ci
npx expo start --lan
```

4. השאירו את הטרמינל פתוח. ב־iPhone סרקו את ה־QR במצלמה ופתחו ב־Expo Go. ב־Android פתחו Expo Go וסרקו את ה־QR מתוכו.
5. השלימו את השאלון או המשיכו מהפרופיל שנשמר באותו מכשיר. נתוני המחשב אינם מועברים אוטומטית לטלפון.

אם החיבור נכשל, בדקו רשת משותפת והרשאת חומת אש לרשת הפרטית. אם Expo Go מציג חוסר תאימות, בדקו את גרסתו לפני שינוי התלויות. קיימת גם אפשרות ל־development build לפי [הוראות Expo](https://docs.expo.dev/guides/local-app-development/): `npx expo run:android --device` עם Android SDK, או `npx expo run:ios --device` ב־macOS עם Xcode וחתימה. לא נוצרו כאן APK/IPA חתומים ולא הופעלו שירותי בנייה בתשלום.

## מה מחובר לנתונים

- שאלון בן חמישה שלבים: פרופיל, סוג אימון, יעדים, זמינות והעדפות, סיכום ובניית תוכנית. טיוטה נשמרת, גם בעריכת פרופיל. משתמש חוזר מגיע ל״היום״.
- גבר/אישה לצורך חישובים, בנפרד מסגנון דמות נשי/גברי, גוון עור, שיער וחולצה. אין הסקת נתוני גוף מבחירת דמות.
- בדיוק שלושה מסלולים: **אימוני כוח, אימוני ריצה, שניהם**. כוח בלבד מתאים גם לירידה בשומן ולשינוי הרכב גוף; אין תוספת ריצה מחייבת.
- יעד ריצה, קצב דקות:שניות לק״מ ותאריך; יכולת נוכחית, הליכון/בחוץ ושיפוע. מהירות הליכון מחושבת מהקצב ומסומנת בהתאם. מטרת גוף ומשקל יעד נפרדים מסוג האימון.
- שלוש לשוניות: **היום, התוכנית שלי, התקדמות**. בתוכנית שלי יש אימונים ותזונה. היום מראה תכנון מול ביצוע, רישום ארוחה ופתיחת אימון. פתיחת אימון אינה רושמת ביצוע.
- מסגרת שבועית לפי המסלול, הימים והמשך שנבחרו, כולל מנוחה בימים האחרים. מסלול משולב דורש לפחות שני ימים. גרסאות התוכנית נשמרות ואינן משנות רישומי ביצוע ישנים.
- אומדן אנרגיה אישי מנתוני גבר/אישה, גיל, גובה, משקל שנמדד ורמת פעילות. כברירת מחדל זה **אומדן תחזוקה**, ללא הפחתה או תוספת אוטומטית לפי מטרת גוף. אפשר להזין יעד קלורי אישי שנקבע עם איש מקצוע. כשאין קלט מתאים מוצגת בקשה להשלמתו, ולא מספר מומצא.
- חלבון, שומן ופחמימות: גרמים שנאכלו מול יעד, אחוז התקדמות בגרמים, אחוז מהקלוריות שנאכלו וחלוקת היעד המתוכננת. אותה פונקציית סיכום משמשת בכל המסכים. חישובים נעשים בדיוק מלא; עיגול נעשה רק בתצוגה.
- יומן ארוחות ידני לפי הערכים בתווית או מקור ידוע: שם וכמות בטקסט, תאריך, קלוריות ומאקרו. הוספה, עריכה ומחיקה מעדכנות את הסיכומים. ערך חסר נשמר כ־null; אין השלמת ערכי מזון אוטומטית.
- יומן ביצוע אימונים ומנוחה: סוג, דקות בפועל, מרחק ריצה, מאמץ והערות, עם עריכה ומחיקה. קלוריות מאימון אינן נוספות אוטומטית לתקציב האכילה.
- יעד יומי נשמר בתצלום קבוע. שינוי פרופיל או מטרה באמצע יום אינו משנה יעד שכבר נקבע או ימים קודמים. יעד חסר יכול להתמלא לאחר השלמת הפרופיל; התוכנית החדשה משמשת ימים חדשים.
- מדידות משקל והיקפים, תיקון רישום, יחידות, תאריך וצד גפה; השוואה מספרית, גרף ואווטאר. היסטוריה אינה נמחקת בשינוי פרופיל, שם, מטרה או דמות.
- אומדן RFM מתועד רק עם קלט מתאים ואישור מדידה לפי NHANES. האומדן והקלט נשמרים יחד עם המדידה, כך שעריכת הפרופיל אינה משכתבת אומדנים ישנים. לא מוצגת מסת שריר. פירוט: [שיטות החישוב](docs/METHODS.md).

## מה עדיין דוגמה ומה נשאר

**תוכן האימונים ורעיונות הארוחות מסומנים כדוגמאות.** המסלול, זמינות, יעדי ריצה, מסגרת השבוע, יומני הביצוע והסיכומים מחוברים לפרופיל ולרישומים. רצפי תרגילים, סטים/חזרות, עצימות, התקדמות ריצה ותפריט בכמויות אינם עדיין תוכנית מקצועית אישית. העדפות ואלרגיות נשמרות, אך רעיונות הארוחות אינם מסוננים לפיהן. הדוגמאות אינן נספרות כביצוע או כאכילה.

להמשך: ספריית תרגילים ותבניות מקצועיות, תכנון עומסים והתקדמות, התאמת תפריט בכמויות ומאגר מזון, התאמת יעדי אנרגיה לפי מטרה ובדיקה מקצועית. כמו כן, פרופילים משפחתיים באותו מכשיר, ייבוא/שחזור, סנכרון, התראות, AI וחיבורי בריאות. צילום אוכל אינו בהיקף.

## שמירה ושדרוג בלי אובדן היסטוריה

פרופיל מקומי אחד בכל התקנה. `profileId` קבוע משייך מדידות, תוכניות, יעדים יומיים, ארוחות, אימונים והעדפות לאותו אדם. שינוי שם אינו יוצר אדם חדש.

AsyncStorage נשאר במפתח הקיים `fitli.local.v1`, עם סכימה 2 בתוך הנתונים. שדרוג מסכימה 1 שומר קודם עותק מדויק ב־`fitli.backup.before-v2`, ואז משייך את הרשומות הקיימות למזהה הפרופיל. תאריכים, מזהי מדידות, ערכים והעדפות נשמרים. שדות שלא נאספו בעבר נשארים חסרים; שיטת מדידת מותניים ישנה נשארת ״לא ידועה״. לכן לפרופיל קיים עשויה להופיע בקשה להשלמת הנתונים לפני יצירת אומדן תזונה.

כתיבות מסודרות בתור, כתצלום נתונים אחד, ורק הצלחת הכתיבה מעדכנת את המצב. כשל קריאה, פורמט לא נתמך או נתון פגום אינם מאפסים את השמירה. תיקון מחליף את הרישום שנבחר בלבד ושומר את מזההו ומועד יצירתו.

הנתונים אינם נשלחים לשרת AI או לענן. השמירה אינה מוצפנת ברמת האפליקציה. הסרת האפליקציה/ניקוי נתוניה עלולים למחוק היסטוריה. ייצוא JSON דרך השיתוף כולל את התצלום הפעיל; אין כרגע ייבוא. איפוס מפורש של הנתונים הפעילים דורש אישור, ומשאיר את גיבוי הגרסה הישנה שנוצר בשדרוג, אם קיים. גיבוי זה הוא עותק מקומי ואינו גיבוי חיצוני.

## עיצוב ונגישות

שפה מקורית עם סגול, קורל, ליים ולבנדר, דמות ליווי מאוירת ואווטאר אנושי עם הצללה. גופן Heebo מצורף לבאנדל. האיורים מקוריים בקוד SVG.

הממשק RTL גם כשהמכשיר באנגלית. כפתורים לפחות 48 נקודות, גלילה, safe areas וטפסים המתאימים למקלדת. טקסט מכבד הגדלה במערכת ללא חסימת scaling; בהעדפות יש גם 100% / 125% / 150%. פריסת ההשוואה עוברת לטור במסך צר או בטקסט גדול. תוויות בעברית, מצבי בחירה לקוראי מסך והכרזת שגיאות. הפחתת תנועה במערכת מכובדת לצד העדפה באפליקציה.

האווטאר שומר זהות, תנוחה וקנה מידה בהשוואה. רק היקפים שהוזנו בשתי הנקודות ובאותו צד משפיעים על האזור המתאים, עד 12% שינוי רוחב לכל כיוון. מותניים בשיטות שונות אינם מושווים. משקל, ימים ויעדים אינם ממציאים שינוי גוף. הכיתוב הקבוע: **״המחשה מסוגננת לפי הנתונים שהזנת״**.

## בדיקות מפתחים ותוצאות

```powershell
npm run typecheck
npm run lint
npm test
npm run export:native
```

`npm run check` מריץ טיפוסים, lint ובדיקות. בסבב 07.10.2026: typecheck ו־lint עברו, **29/29 בדיקות עברו**, וייצוא Hermes ל־iOS ול־Android עבר. הפלט ב־`dist/native` הוא bundle, לא APK/IPA ולא הרצה במכשיר. פרטי בדיקות הדפדפן, ההגירה, הארוחות והמאקרו ב־[דוח הבדיקות](docs/TESTING.md). תמונות ב־[artifacts/screenshots](artifacts/screenshots).

בדיקות Web בוצעו במחשב Windows, בדפדפן המובנה של Codex, ברוחב 320 ו־390 פיקסלים ובתצוגת מחשב, כולל הגדלת טקסט ל־150%, רענון וסגירת לשונית ופתיחתה מחדש. **לא נבדקו iPhone/Android אמיתיים, סימולטור או אמולטור, VoiceOver או TalkBack.**

## בדיקת קבלה בטלפון

1. בנו פרופיל עם נתוני חישוב, משקל ורמת פעילות. בחרו כוח בלבד וירידה בשומן/שינוי הרכב גוף. ודאו שאין ריצה כפויה. נסו גם ריצה ומשולב, כולל קצב, תאריך, יכולת והליכון/בחוץ.
2. ודאו שב״היום״ יש יעד אישי ותכנון היום; ארוחה מתוכננת ופתיחת אימון אינם מוסיפים רישום בפועל. ביום מנוחה מוצג חיזוק למנוחה.
3. תעדו ארוחה עם 200 קלוריות, 20 גרם חלבון, 5 גרם שומן ו־18 גרם פחמימות. חלבון הוא 40% מהקלוריות שנאכלו, בנפרד מההתקדמות בגרמים. שנו ל־150 קלוריות ו־15 גרם חלבון, ודאו שאין כפילות, ומחקו באישור. אלה נתוני בדיקה בלבד.
4. תעדו ביצוע אימון. שנו שם, מטרה, סוג אימון ודמות. בדקו שהרישום ומזהה הפרופיל נשארו ושהיעד שכבר נקבע להיום נשמר.
5. הוסיפו שתי מדידות חלקיות עם תאריכים וצדי גפה. ודאו שאין שינוי באזור בלי שני ערכים תואמים. נסו מותניים בשיטה לא ידועה; לא יופיע אומדן RFM. בחרו NHANES רק כשכך נמדד בפועל.
6. **סגרו לגמרי את Expo Go ופתחו מחדש את אותו פרויקט.** בדקו פרופיל, מדידות, תוכנית, יומנים, טיוטה והעדפות. אין לנקות את נתוני Expo Go. שרת הפיתוח צריך לפעול.
7. נסו גופן גדול במערכת ו־150% באפליקציה, VoiceOver/TalkBack, מסך קטן, notch, מקלדת ומצב landscape. ודאו שכל הטפסים נגללים וכל פעולה נגישה. בדקו Reduced Motion במערכת ובאפליקציה.
8. נסו קלט חסר, קצב לא תקין ותאריך עתידי למדידה/ביצוע. שגיאה צריכה להופיע בעברית בלי רישום חדש. אל תאפסו נתונים אמיתיים לצורך בדיקה.

## תלויות ומבנה הקוד

לא נוספו תלויות בסבב התיקונים. בבדיקה הקודמת (06.10.2026), `expo-doctor` עבר 21/21. `npm audit` מאותו יום דיווח על 28 התראות עקיפות; [הדוח שנשמר](docs/npm-audit.json). דוח זה לא הורץ מחדש בסבב הנוכחי. לא הופעל `audit fix --force` ששינה גרסאות Expo. נדרש טיפול נפרד לפני הפצה רחבה.

- `src/app`: מסלולים, שאלון, לשוניות ועריכת רישומים.
- `src/components`: רכיבי עיצוב, אווטאר, סיכום תזונה, יומן והשוואה.
- `src/domain`: סכימה, אימות, תכנון, תזונה, RFM והשוואות.
- `src/data`: שמירה, הגירה וספק מצב React.
- `tests`: בדיקות כללי דומיין, הגירה, שמירה וכשלים.
- `docs/PLAN.md`: החלטות סבב התיקונים; `docs/METHODS.md`: נוסחאות ומקורות; `docs/TESTING.md`: בדיקות בפועל.

מקורות פיתוח: [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/), [Expo Router](https://docs.expo.dev/versions/v57.0.0/sdk/router/), [RTL ב־Expo](https://docs.expo.dev/guides/localization/), [נגישות React Native](https://reactnative.dev/docs/accessibility).
